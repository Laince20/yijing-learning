# 语音学习与学习模式

## 一句话说明

这个项目把 Codex 当作“会备课的学习伙伴”，把 Qwen TTS 当作“朗读老师”。Codex 负责先读资料、拆知识点、记录进度；Qwen TTS 负责把讲解变成更适合听的语音。

## 为什么用语音

《易经》的概念很容易一上来就变成术语堆叠。语音学习的好处是让讲解慢下来，一次只听一个知识点，先形成直觉，再回到文字笔记复盘。

所以本项目不是先追求资料量，而是追求一个节奏：

1. 先讲得听懂。
2. 再用例子落地。
3. 再回到原文和结构。
4. 最后压缩成可以复述的一两句话。

## Qwen TTS 在项目中的角色

Qwen TTS 只负责把已经备好的讲解朗读出来，不负责替代阅读、判断或笔记。

默认流程是：

1. Codex 读取 `学习资料/学习进度.md`，确认今天从哪里继续。
2. Codex 回到主书或已有笔记中备课。
3. Codex 写出适合听的一小段讲解。
4. 调用 Qwen TTS 朗读。
5. 等语音播放结束，再保留简短文字版，或继续下一小段。
6. 学习结束后更新进度和课程笔记。

## 语音使用规则

- 一次只朗读一个小知识点，不把长篇文档整段灌进去。
- 内容可以讲厚，但语音要分成编号小节。每个音频片段只承担一个清楚任务，例如“定义泰卦”“定义否卦”“用错题本类比泰否”。
- 重要定义、原文、读音和结论不要只放在音频最后一句；最后一句尽量使用“这一小节到这里”之类的非关键信号，防止尾部丢失影响理解。
- 尽量控制在 30-60 秒一个音频片段；用户明确要求多输入时，可以连续播放多个片段，而不是合成一个超长片段。
- 语言要适合听：短段、慢节奏、有停顿，不堆术语。
- 调用 TTS 后等待播放完成，再进入下一段讲解。
- 如果用户反馈“没播完”，立即停止新内容，改成更短片段重播缺失部分，或等用户确认后再继续。
- 如果用户觉得音色不舒服，先用短句试音，再继续讲课。
- 如果 Qwen TTS 失败，说明失败原因，并临时用 macOS `say` 或文字继续。

## 稳定播报调用

Qwen TTS wrapper 当前流程是：

1. Codex 把要朗读的文本传给脚本。
2. 脚本调用 Qwen TTS 生成一个 wav 音频文件。
3. 脚本用 macOS `afplay` 同步播放。
4. 播放结束后脚本再等待 `QWEN_TTS_POST_PLAY_SLEEP` 秒，默认 5 秒。

为降低尾部丢字或播放感知不同步，较长片段默认使用：

```bash
QWEN_TTS_MAX_TOKENS=2048 QWEN_TTS_POST_PLAY_SLEEP=8 /Users/xuhanpeng/Documents/Codex/2026-06-16/new-chat/outputs/codex-speak-qwen "要朗读的文字"
```

如果用户说“后面没播到”，立即只重播缺失部分，不继续讲新内容。

## 分段音频工作流

用户已明确可以接受多个音频文件。为提高稳定性，语音课优先使用项目脚本分段生成和播放：

```bash
学习资料/tools/speak_sections.sh "第一小节文本" "第二小节文本" "第三小节文本"
```

这个脚本会：

1. 每个小节单独调用 Qwen TTS 生成一个 wav 文件。
2. 用 `afinfo` 检查音频文件存在且有时长。
3. 用 `afplay` 逐段同步播放。
4. 每段播放后短暂停顿。

使用原则：

- 每段只讲一个任务：定义、原文、例子或总结。
- 如果某段没播完，只重播那一段，不重播整课。
- 文字稿可以完整保留，语音稿按小节拆开。

## 新概念语音顺序

以后引入新卦名或术语时，不能直接拿来做例子。先按这个顺序讲：

1. 名字和读音。
2. 在体系里的位置。
3. 卦象或结构。
4. 主书原文。
5. 白话定义。
6. 再拿它解释当前知识点。

## 学习模式怎么建立

这个学习模式由四层文件共同建立：

1. `AGENTS.md`：项目总规则。它规定每次讲解前先读资料，默认中文教学，语音优先，一课只聚焦一个知识点。
2. `.agents/skills/yijing-study/SKILL.md`：专用 skill。它规定主书、辅助书、外部知识库的使用顺序，以及如何备课和产出课程笔记。
3. `学习资料/学习计划.md`：课程地图。它规定先学基础观念，再学结构、八卦、读卦方法、乾坤示范和六十四卦。
4. `学习资料/学习进度.md` 与课程笔记：课程记忆。它记录已经讲过什么、哪里还卡住、下次从哪里继续。

建立顺序可以复用为：

1. 先确定学习目标：不是快速结论，而是长期理解体系。
2. 再确定资料分工：主书为依据，辅助书和知识库只做补充。
3. 再确定教学节奏：先读薄、用例子落地、再读厚、诵读句、最后再读薄。
4. 再确定交互规则：不急着结课，等用户追问、复述或确认。
5. 最后建立记录机制：每次学习后更新进度和笔记。

## 一次学习的实际循环

```text
用户说“今天继续”
-> Codex 读取学习进度
-> 回到主书或笔记备课
-> 用 Qwen TTS 朗读一小段
-> 停住，等待用户确认听完
-> 用户追问或复述
-> Codex 换例子、补原文或修正理解
-> 更新学习进度和课程笔记
-> 下次继续
```

这个循环的关键不是讲得多，而是每次都让理解往前稳稳走一步。

## 一次学习的收束循环

用户说“今天到这儿”时，不直接结束，而是做一次阴阳闭环：

1. 回顾今天的核心知识点。
2. 记录用户自己的复述、例子和卡点。
3. 分析本次教学流程哪里顺、哪里不顺。
4. 把稳定改进写回 skill、学习模式、资料索引或学习进度。
5. 给下次学习留下清楚入口。

这个收束本身也按阴阳理解：

- 阳：Codex 输出讲解、推进课程、调用资料、播放语音。
- 阴：用户听、消化、追问、指出跳步和不稳定之处。
- 化：Codex 把反馈吸收进流程，下一次输出更稳、更厚、更有依据。

后续优化重点：

- 讲新概念时先定义，再举例。
- 讲课时默认采用“完整小单元”，避免过度碎片化。
- 语音继续使用先生成后连续播放的分段流程。
- 每次正式讲新内容前，优先检查主书和 `学习资料/资料索引/三书使用地图.md`。
- 学习结束时必须写入当天学习记录，并更新下次入口。
