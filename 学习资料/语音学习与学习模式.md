# 语音学习与学习模式

## 一句话说明

这个项目把 Codex 当作“会备课的学习伙伴”，把 Qwen TTS 当作“朗读老师”。Codex 负责先读资料、拆知识点、记录进度；Qwen TTS 负责把讲解变成更适合听的语音。

## 为什么用语音

《易经》的概念很容易一上来就变成术语堆叠。语音学习的好处是让讲解慢下来，一次只听一个知识点，先形成直觉，再回到文字笔记复盘。

所以本项目不是先追求资料量，而是追求一个节奏：

1. 先讲得听懂。
2. 再用例子落地。
3. 再回到原文和结构。
4. 最后压缩成可以复述的一两句话。

## Qwen TTS 在项目中的角色

Qwen TTS 只负责把已经备好的讲解朗读出来，不负责替代阅读、判断或笔记。

默认流程是：

1. Codex 读取 `学习资料/学习进度.md`，确认今天从哪里继续。
2. Codex 回到主书或已有笔记中备课。
3. Codex 写出适合听的一小段讲解。
4. 调用 Qwen TTS 朗读。
5. 等语音播放结束，再保留简短文字版，或继续下一小段。
6. 学习结束后更新进度和课程笔记。

## 语音使用规则

- 一次只朗读一个小知识点，不把长篇文档整段灌进去。
- 语言要适合听：短段、慢节奏、有停顿，不堆术语。
- 调用 TTS 后等待播放完成，再进入下一段讲解。
- 如果用户觉得音色不舒服，先用短句试音，再继续讲课。
- 如果 Qwen TTS 失败，说明失败原因，并临时用 macOS `say` 或文字继续。

## 学习模式怎么建立

这个学习模式由四层文件共同建立：

1. `AGENTS.md`：项目总规则。它规定每次讲解前先读资料，默认中文教学，语音优先，一课只聚焦一个知识点。
2. `.agents/skills/yijing-study/SKILL.md`：专用 skill。它规定主书、辅助书、外部知识库的使用顺序，以及如何备课和产出课程笔记。
3. `学习资料/学习计划.md`：课程地图。它规定先学基础观念，再学结构、八卦、读卦方法、乾坤示范和六十四卦。
4. `学习资料/学习进度.md` 与课程笔记：课程记忆。它记录已经讲过什么、哪里还卡住、下次从哪里继续。

建立顺序可以复用为：

1. 先确定学习目标：不是快速结论，而是长期理解体系。
2. 再确定资料分工：主书为依据，辅助书和知识库只做补充。
3. 再确定教学节奏：先读薄、用例子落地、再读厚、诵读句、最后再读薄。
4. 再确定交互规则：不急着结课，等用户追问、复述或确认。
5. 最后建立记录机制：每次学习后更新进度和笔记。

## 一次学习的实际循环

```text
用户说“今天继续”
-> Codex 读取学习进度
-> 回到主书或笔记备课
-> 用 Qwen TTS 朗读一小段
-> 用户追问或复述
-> Codex 换例子、补原文或修正理解
-> 更新学习进度和课程笔记
-> 下次继续
```

这个循环的关键不是讲得多，而是每次都让理解往前稳稳走一步。
